# 多目标航迹关联与生命周期管理

纯 Go 标准库实现的传感器多目标跟踪演示：全局最优观测-航迹关联、航迹生命周期
管理、抗噪声代价设计，并生成单文件 HTML 回放报告（原生 HTML/CSS/JS，无任何
第三方依赖，不启动服务）。

## 运行

```bash
go run . -o report.html      # 仿真演示场景并生成回放报告（浏览器直接打开）
go run . -o report.html -seed 7   # 换随机种子
go test ./...                # 运行全部自动化测试
```

演示场景（100 帧，含随机杂波）：

- **T0 / T1**：第 ~38 帧交叉，验证歧义分配下不发生身份交换；
- **T2**：第 15 帧出现、第 55 帧消失，验证新生/消亡判定；
- **T3**：第 30–34 帧被遮挡（5 帧），验证遮挡恢复回原航迹；
- 每帧叠加随机杂波点，验证噪声点不产生航迹抖动。

## 关联算法：带虚拟行列的匈牙利算法（全局最优）

逐帧关联**不**采用贪心最近邻，而是构造代价矩阵求**全局最优二分图匹配**
（`hungarian.go`，O(n³) 匈牙利算法，手工实现，无第三方图论库）。

代价矩阵为 `(航迹数+观测数)²` 的方阵：

| | 观测列 j | 虚拟列（每航迹一列） |
|---|---|---|
| **航迹行 i** | 可行对的平方马氏距离；超门限对填 `bigCost`（不可行） | 对角 = 门限 Gate2（航迹不关联的代价） |
| **虚拟行（每观测一行）** | 对角 = 门限 Gate2（观测不关联的代价） | 0 |

这一构造保证：

- **全局最优**：交叉场景下两条航迹的关联代价重叠时，求解器比较的是
  总代价，而不是逐条贪心抢占，因此不会产生身份交换；
- **允许不关联**：任何优于门限的真实匹配都优于"不匹配"，而超门限的
  观测-航迹对**永远不会被强制关联**——观测和航迹都可以在该帧保持未关联；
- 匹配结果中，航迹匹配到虚拟列即本帧漏检，观测匹配到虚拟行即候选新目标。

## 关联代价与门控（抗噪声设计）

- 每条航迹由匀速模型卡尔曼滤波器维护（`kalman.go`，状态 `[x, y, vx, vy]`，
  4×4 矩阵运算手工展开）；
- 关联代价为**平方马氏距离** `d² = yᵀS⁻¹y`（新息 `y`，新息协方差
  `S = HPHᵀ + R`）。它按滤波器自身不确定度归一化：航迹不确定时门控自动放宽，
  收敛后自动收紧，因此对观测噪声鲁棒；
- 门限 `Gate2 = 9.21`（χ²(2) 分布 99% 分位）：`d² > 9.21` 的对为不可行匹配；
- **遮挡期间冻结门控协方差**：滑行时 `P` 持续增大，若直接用当前 `S`，
  门控区域会膨胀到吞掉邻近目标的观测（实测曾导致交叉目标身份被夺）。
  进入滑行的第一帧冻结 `S`，之后整个遮挡期都用它计算代价，搜索区域保持
  在丢失时的大小。

## 航迹生命周期

```
孤立观测 → 试探航迹 ──连续 ConfirmHits=3 帧关联──→ 确认航迹
              │                                      │
              └── 任意一帧未关联即丢弃 ──         连续 MaxMisses=5 帧未关联 → 消亡
                                                   │
                                            漏检 ≤5 帧：滑行（纯预测外推），
                                            恢复观测后重新关联回原航迹，ID 不变
```

- **新生**：未关联观测只创建*试探航迹*；连续 3 帧关联成功才转为*确认航迹*
  （事件 `born`）。孤立噪声点下一帧即被丢弃（事件 `dropped`），不会建立航迹；
- **消亡**：确认航迹连续 5 帧未关联才删除（事件 `died`），单帧漏检只是滑行；
- **遮挡**：确认航迹首次漏检进入滑行（事件 `occluded`），期间只做时间更新
  外推；阈值内重新关联即恢复（事件 `recovered`），**身份不变、不产生新航迹**；
  超过阈值才按真正目标消失处理。

参数集中在 `Config`（`tracker.go`）：`Gate2` / `ConfirmHits` / `MaxMisses` /
`ProcessNoise` / `MeasNoise`。

## 回放报告

`go run .` 生成的 `report.html` 为完全自包含的单文件（数据内嵌为 JSON，
原生 Canvas 渲染）：逐帧播放/单步/拖动进度，观测点、航迹（含尾迹与关联
连线）、试探/滑行状态，以及新生（绿圈）、消亡（红叉）、遮挡（橙色虚线圈）、
恢复（蓝色双圈）事件高亮；右侧事件日志可点击跳转，并给出身份保持率、
ID 切换次数等统计。

| 测试 | 验证点 |
|---|---|
| `TestHungarianMatchesBruteForce` | 随机矩阵（含不可行项）上匈牙利结果与暴力枚举最优值一致 |
| `TestHungarianRejectsInfeasiblePair` | 超门限观测不被强制关联，航迹保持未关联滑行 |
| `TestCrossingNoIdentitySwap` | 两目标交叉全程无身份交换、无误消亡 |
| `TestConfirmationThreshold` | 连续 3 帧才确认；孤立噪声点不产生航迹 |
| `TestDeletionThreshold` | 连续漏检 >5 帧才消亡；单帧漏检不删除 |
| `TestOcclusionRecovery` | 5 帧遮挡后恢复原航迹 ID，无新生/消亡 |
| `TestIdentityPreservationUnderNoise` | 加噪+杂波完整场景：身份保持率 ≥95%、0 次 ID 切换、新生/消亡数正确 |

当前演示场景指标：身份保持率 100%，ID 切换 0 次。
